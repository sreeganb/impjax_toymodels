# Complete skeleton for the implementation of the code in plain english text

## This is going to do bayesian inference of models, the input data is experimental data from experiments such as crosslinking MS, cryo EM, SAXS, fluorescence spectroscopy, NMR, etc. The restraints are going to be spatial restraints between particles that are usually part of a protein or a protein complex. The final models will be 3D spatial coordinates of these residues or mostly within IMP we do coarse graining as well as define rigid bodies where possible such that we have not a lot of degrees of freedom to worry about when it comes to sampling these structures of highly heterogeneous systems where data is sparse as well as the system complexity is so high that we do not even know the copy number of proteins in the complex that we are trying to infer, therefore we define and use nuisance parameters that could be sampled and inferred as well apart from the regular model parameters. 
## IMP is used to read in input information such as pdb files, topology files,      experimental data such as crosslinking data, cryo em densities, APMS data and so on.
## User will use the run script to do this part, generation of the IMP input representation as well as definition of the scoring function and generate the JAX restraint scoring function which is JIT compiled so that external samplers can come in and simply use this object along with the degrees of freedom and run sampling using modern samplers. 
## The functions have to be very small and do specific tasks, for example, there has to be a function in the wrapper that simply reads in a model, hierarchy and extract all sorts of information about the system such as rigid body indices, rigid body coordinates, flexible beads coordinates and indices, and unit tests are added to properly make sure that this part is well tested.
## There has to be function that will list out all of the particles (rigid bodies as well as flexible beads that are to be sampled.)
## In each file, my design philosophy is to keep the length of the file to be less than 200-300 lines, which I think I want to strictly adhere to, the wrapper could be longer I guess because I want that to be the pipeline and the only pipeline that the user would access in order to setup IMP in some script that they have and then use the wrapper and run sampling using blackjax samplers. I already have some working SMC and RMH samplers implemented which I took from blackjax, meaning, I have an input file which will interface with these samplers in blackjax, I have not written these samplers myself which is also the ultimate goal and what I want to adhere to at all cost, I only want to provide inputs to the samplers that already exist within blackjax, there is absolutely no reason and doesnt make any sense for me to reimplement any of these myself. 
## The goal of this project is simple: there is IMP which can do multiscale representation very well and it has several highly optijmized scoring functions implemented inside of it which are based on experimental data such as crosslinking mass spec, cryo EM, protein specific restraints such as connectivity, excluded volume, etc. recently JAX versions of the model defenition as well as scoring functions are available within IMP, which means the scoring functions can now be computed in a GPU. I want to extend this, using a wrapper and compute not just scoring functions but the entire model posterior distribution using blackjax sampling and all of the implemented JAX features. 
## So, I need to create lots of unit tests, I have added some files already in the repo to do some testing, it has some very essential code which contains information on how exactly the IMP system needs to be defined and how the whole setup needs to work in terms of IMP. Now, I need to port in the blackjax files. 
## I have included samplers that are rmh and smc samplers. Generation of proposal is a great problem that needs to be solved, we usually have rigid bodies and flexible beads to be sampled within IMP, meaning we have quaternions and 3D coordinates that need sampling. These are obviously of different scales, quaternions rotate rigid bodies which are much larger than flexible beads wherein a flexible bead might contain few residues, a rigid body could contain 10s to a couple hundred residues sometimes. I want a separate function that will generate proposals in a smart way for these different scale parameters, this is a non-negotiable entity, I need a separate file and separate functions that do rigid body rotations, rigid body translatiomns and then also do flexible bead translations. These also need tests that need to pass. Rigid body rotations need to make sure that they are SO3 compliant, meaning they need to sample rotations in a mathematically accurate way. The proposals have to respect detailed balance in sampling, this is again non-negotiable.
## The style of the code has to be consistent across the repo, for example writing comments is non-negotiable, this needs to be done in a great and detailed fashion so that there is no doubt about what a variable or a function/class is out there to do. 
## Output is usually written in the form of stat files as well as rmf3 trajecotry files to be visualized later on within IMP and I want to use the same mechanism to write the trajecotry files because its essential, but in a GPU we have limited memory right and constant IO in and out of the GPU onto the CPU is expensive, so I need to put in thought to come up with modern and industry standard solution for GPU codes that implement some awesome methods to do this, how can this be achieved without compromising on the speed that we are so dearly after. So I need separate modular functions in separate files dealing with IO which is again non-negotiable.
## Always do things in a modular fashion, so if things fail, I can simply remove some files or parts of code and get back to the point when things worked fine. Also create smaller commits to the git repo since that helps a lot in maintaining the health of the git repo. 
## I want the different modes of sampling to be chosen by the user, for example, sample only rigid body rotations, or only rigid body translations, or sample only rigid body (rot + trans) or sample only flexible beads, or the final option, sample all of the degrees of freedom, this has be non-negotiable as well. 
## I want to be able to go smoothly from IMP/IMPJAX scoring functions to probabilities that are used as optimizer functions within blackjax samplers, and also, I want to generate sampling convergence metric from within of blackjax, I am sure that there are some functionalities to do this, and I want to use this, it has to be different self contained modular file as always and its non-negotiable to do this.
